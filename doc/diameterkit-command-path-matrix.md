## 1. 行键、证据与统计边界

每行键为`LeafID.Command`，代表固定App、Command、R/E=正常语法、完整Vendor:Code父路径和直接父实例的叶数量。这个键只是表格定位，不新增SPEC/RuleID体系。18种命令见§2，SGd/Gdd/T4角色差异再见§4；不能用相同App-ID证明接口/方向等价。`0:266`与`10415:266`不同；父组可重复时，数量限制逐个父实例执行，不将另一组的子项借入当前组。

“在位候选”只说明此命令/路径存在类型可表示的字段，不代表整个请求/答案、终端广告、外部事实或所有叶条件有效。旧候选勘误照常适用；选取时排除已明确降级的M0请求与漏SMEA请求。样本包含某叶不等于测试过该叶的错误；“定向反例”收纳显式指定此叶且命令相同的N22/N24/N25/N26/N27/N28/N29/N30/N31记录，既包括静态字段也包括明确结果/应用条件反例。纯父组组合反例继续在§4/主流程保留，不随意分摊给组内每一叶。`—`表示此项没有纳入该类精确证据，不代表规范允许省略该叶，也不声称全仓库不存在相关字节。继承的复合负例只证明目标问题，不声称除目标外整pair均合法。

允许、条件、禁止、仅结构边界和具名兼容分开。禁止位置不配置“成功样本”；结构边界不能升级为已启用helper。A/B/D/C沿用逐叶清单S1–S19，**作用于该叶被使用的场景，不能复制成表中每个命令都有生产调用**。UI-SMS在SRA/RDA的User-Name、TFA的MSISDN及External-Identifier/LMSI结构列特意保留边界，不能代替所选过程要求的Alert MSISDN或Router token。

本文检查现有输入的路径/条件，不需要业务存储，也不扩大validation.Context。每行的类型、发送flags及直接父实例次数引用111叶定义；命令语法条件可收紧，如PUR/PNR的702为必需、UDA/SNA为条件项，不能继承统一0..1后漏检。Sh628 M位按发送用途处理，不能把它推广为所有SMS命令的固定值。
